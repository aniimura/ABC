## 一行でいうと

> **打点して道を炙り出すのではない。打点して地図を書き直す。**

「論文＝大きな主張＋確信つきの論理の骨組（スケルトン）」というオブジェクト化は正しい。
しかし打点の帰結は「その点が閉じたか否か」の 2 値ではなく、**5 値**である ——
閉じた / 割れた / 読み違えていた / **偽だった** / 仮定を足せば閉じる。
このうち 4 つは**地図そのものを書き換える**。

したがってエージェントに要るのは「証明する能力」だけではなく、
**自分の地図が間違っていたことを検出して直す仕掛け**である。
`02-method.md` はその仕掛けを 6 つの台帳と 1 つのループとして書く。

## 前提としている状況

* 最終目標が**遠い**（本プロジェクトなら IUT 全体 ＋ abc）
* 経由すべき論文が**既に存在する**（自分で発見するのではない）
* 形式化系（Lean 4 + mathlib）という**外部の審判**が使える
* エージェントは**長時間・多セッション**で走る

★この 3 つ目が効いている。審判が無い場合の方法論は本書の射程外である
（`03-external-validation.md` §4 に、そこがどう変わるかの見立てを書く）。
