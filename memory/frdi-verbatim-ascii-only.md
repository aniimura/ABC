`tools/check.mjs` の逐語照合は **PDF の layout 抽出**と突き合わせるが、
`ResearchPaper/0_Source/*.txt` の抽出とは**字が違う**文字がある。
確認済みで落ちるもの: `▷` `′` `⪯` `≼` `̸=` `↪` `ϵ` `±1`(layout は `±` だけ)、
`𝔽_Φ`→`FΦ`。★**txt から splice しても落ちる**(txt と layout で codepoint が違う)。

**Why:** 2026-08-16〜17 だけで 6 回この事故を起こした。手で打つのはもちろん、
txt から機械的に splice しても `▷` を含む行は通らない。

**How to apply:** 引用は必ず **ASCII だけの連続断片**に切る。手順:
1. 該当ページのテキストを取り出す
2. 目印の語から始めて、**最初の非 ASCII 文字の直前で切る**
3. 25 文字以上あることを確認し、正規化(空白除去)して同ページに含まれることを assert
4. その文字列を Lean ファイルへ書き込む

★連続する `>` 行は**1 ブロック**として原典の連続行と照合されるので、
別々の引用にしたいときは `原文 (FrdI p.NN):` の見出しで分ける。
★`原文 (FrdI p.NN):` のページ番号は**物理ページ**(`===== [page N] =====`)であり、
語の初出ページとは限らない(§0 の skeleton は p.11 ではなく p.15 だった)。

★★**台帳の note のページ番号を docstring へ写さない**(2026-08-19 実測)。
`frdi-decomposition.json` の note は「その**主張**が載るページ」を書いており、
docstring の `原文 (TAG p.N)` が要るのは「**その引用文**が載る物理ページ」である。
`Theorem 3.4` は主張が物理 p.62、(iv) の**証明**は物理 p.66 で、
台帳の「FrdI p.62」を 4 箇所そのまま写して 3 件のゲート NG を出した。
★引用を書く前に必ず `pdftotext -f <p> -l <p>` で**その文が出るページを実測**すること。

## ★★★★訂正(2026-08-25)—— `-enc UTF-8` を付けないと非 ASCII が**空白に化ける**

`pdftotext` の既定の出力エンコーディングは Latin-1 で、
`⊆` `Φ` `∈` `⟶` などは**黙って空白 1 個に置き換えられる**。
一方 `check.mjs` は UTF-8 で読むので、ゲートの側には `⊆` が**ある**。
つまり「抽出結果を目で見て写す」と、非 ASCII のところだけ空白になった
偽物を写すことになり、`引用照合: 逐語が … に見つからない` で落ちる。

```
pdftotext -enc UTF-8 -f 112 -l 112 -layout "…/The Geometry of Frobenioids I.pdf" out.txt
```

★★したがって上の「ASCII だけの断片に切る」は**必須ではない** ——
`-enc UTF-8` で取れば `⊆` `Φ` `∈` `“ ”` はそのまま通る(2026-08-25 に 3 件で実測)。
落ちるのは `▷` `′` `⪯` など、layout と txt で codepoint 自体が違う文字だけである。
★`ﬁ`(fi 合字)と曲がり引用符 `“ ”` は `check.mjs` 側で正規化されるので、
`finite` / `"` と書いても通る。

★★★**ターミナルに出た文字列をそのまま写さない**。ターミナルは非 ASCII を
落として表示することがある。`node -e` でファイルを読んで
`JSON.stringify(line)` で出すか、`-enc UTF-8` の出力ファイルを直接読むこと。
