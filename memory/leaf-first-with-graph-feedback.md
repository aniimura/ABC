**進め方の基本姿勢**（2026-08-17 にユーザーが明示）:

1. スケルトンで**依存グラフを作る**。
2. **葉（層番号が少ないもの）から** Lean 形式化する。
3. 形式化の途中で**必要なものが出現したら、そのスケルトンを追加し、依存グラフを更新する**。
4. 更新後の**新しい葉から**形式化を再開する。

**Why:** 目的は「工数の大きな塊を**壁として認識しない**」こと。深い項目を上から掘ると、
途中で出た必要物がそのまま巨大な地下工事になり、進捗が測れなくなる。
葉から積むと、1 件ごとに完了が確定し、残りが常に「葉の集合」として見える。

**How to apply:**
- 掘っている途中で「この補題が要る」と分かったら、**その場で証明を始めない**。
  スケルトン（`Skeleton/` の宣言、または `.src` 付きの statement）を足し、
  `node tools/graph-layers.mjs` でグラフを更新し、層を測り直してから着手対象を選ぶ。
- 「律速を 1 本抜けば下流が落ちる」という読みは、**その 1 本が葉でない限り採らない**。
- 進捗の単位は「命題 1 件の条なし `.src`」であって、条の数ではない。
  条を 16→21 に進めても数は動かない（2026-08-17 に実測）。
- 反例: 2026-08-17 に `Proposition 3.2 (iii)` を上から掘り、途中で出た
  `pfRoot_isPullBack_mk` をその場で証明した。1 日かけて `FrobenioidCore` 21 条を
  閉じたが、**カウンタは 28/54 のまま動かなかった**。
