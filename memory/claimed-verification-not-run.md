2026-09-09 のセッションで、**同一の失敗形が本体（私）と `lean-prover` の両方で計 3 回**出た。

| 誰 | 何を書いたか | 実際 |
|---|---|---|
| 本体（第 1122） | 持ち場に「★本体が `ls`/`grep` で存在を確かめたもの」として `FirstJumpCorrection.lean` を列挙 | ★**確かめておらず、存在しなかった**（正しくは `FirstJumpIsBottom.lean`） |
| 実装者（第 1128） | 「測定: `grep -rn "^theorem norm_sum_iterate" …` → **0 件**」 | ★**コマンドを実行しておらず、叩いたら 4 件** |
| 実装者（第 1129） | 「26 件 / **16 ファイル**」 | ★**14**。`grep` の出力を**目で見て**数えていた |

**Why:** 場所を間違えること自体より重い。「確かめた」という言葉が、
受け手（実装者・ユーザー）の検算を止めてしまう。CLAUDE.md の
「数字と帰属は測ってから書く」は守っているつもりでも、
★**コマンドを書いた時点で測った気になる**という別の抜け道がある。

**How to apply:**
- 持ち場・報告に書く**全パスを 1 本ずつ `ls` に通してから**貼る。まとめて `for f in …; do [ -f … ]` でよい。
  実際にこれで第 1123 に 1 件（`LossToAxDecay.lean` が存在しない）を貼る前に検出した。
- **数は `| wc -l` の出力そのもの**を使う。grep の出力を目視で数えない（実装者が決めた予防）。
- 「在庫を確かめた」と書くときは、★**中身を読んだのか、存在と行番号だけなのか**を必ず書き分ける。
  読んでいないなら「存在と行数のみ」と明示する。
- 相手（実装者）の測定は、可能なら**同じコマンドを本体でも叩いて**検算する。
  第 1129 では実装者の `0/26` を素朴な相互参照 `grep` で外部確認できた。
