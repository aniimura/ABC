# 循環は理論の循環か——実測(2026-08-15)

再現: `node tools/cycle-probe.mjs`

## 問い

依存グラフに循環がある(824 節点、最大 SCC = **262 節点**、IUTchI/II/III/IV にまたがる)。
- これは**理論の循環**か。
- **サブグループ化**で解けるか。

## 答え1: 理論の循環ではない。**辺の定義の副作用である。**

我々の辺は「項目の本文が `Kind N.M` を名指しした」である。ここには4種類が混ざる:

| | 種別 | 依存か |
|---|---|---|
| (a) | 証明が実際に依拠している | **依存** |
| (b) | 前方参照(`cf. …, below`) | 依存ではない |
| (c) | 解説への案内(`the discussion of …`) | 依存ではない |
| (d) | Remark(注釈)からの言及 | 依存とは限らない |

**最大 SCC(262 節点)の内部の辺 1487 本の内訳(実測)**:

| 文脈 | 本数 | 割合 |
|---|---:|---:|
| `below`(前方参照) | 176 | 11.8% |
| `the discussion of`(解説案内) | 259 | 17.4% |
| `cf.`(引用。両義的) | 535 | 36.0% |
| Remark **から**の辺 | 289 | 19.4% |
| Remark **へ**の辺 | 21 | 1.4% |
| **どの目印も無い**(依存の可能性が高い) | **207** | **13.9%** |

**辺を落としたときの循環**:

| 落とす辺 | 最大SCC | 循環内の節点 | SCC 数 |
|---|---:|---:|---:|
| (基準) | **262** | 440 | 414 |
| `below` | 114 | 177 | 660 |
| `the discussion of` | 207 | 379 | 477 |
| Remark 発/着 | **10** | 84 | 762 |
| below + discussion | 16 | 81 | 756 |
| **3つ全部** | **8** | 54 | 781 |

### ★★決定的な点: 残った循環は**すべて1論文の中**に閉じる

3つ全部を落としたあとに残る循環は 19 個・77 節点で、**論文をまたぐものは1つも無い**:

```
FrdI      (10) Definition 1.2/1.3/3.1、Proposition 1.4/1.5/1.7/1.9/1.10/1.11/3.3
AbsTopIII ( 8) Definition 2.1/3.1、Proposition 3.2、Lemma 3.4、Corollary 3.6/3.7/1.10、Theorem 1.9
GenEll    ( 8) Proposition 1.4/1.6/1.7/3.4、Theorem 2.1/3.8、Lemma 3.5/3.7
EtTh      ( 7) / AbsTopI (7) / CombGC (5) …
```

**262 節点の論文をまたぐ循環は完全に消える。** すなわち:

> **IUTchI → II → III → IV という順序付けは存在する。**
> 基準のグラフで存在しないように見えたのは、我々が「前方参照」と「解説への案内」と
> 「注釈からの言及」を依存として数えていたからである。

残った 5〜10 節点の塊は、いずれも1つの節の中で定義と命題が互いを参照する
通常の叙述であり、**目で見て解ける規模**である(未実施)。

## 答え2: サブグループ化では循環は解けない。**辺の精密化なら解ける。**

- **循環している塊(SCC)**: 定義により、SCC 内のどの2点も互いに到達する。
  **どう分割しても部分群の間に順序は付かない。** サブグループ化は無力である。
- **循環していない大きなボックス**: これは既に順序付いているので、
  分割は自由であり有効。層 0 の 148 節点を論文ごとに割るのは中期ゴールとして妥当。
- **★循環を解く唯一の方法は辺を減らすこと**であり、上の実測どおり有効である。

### もう1つの手(未実測): statement と proof を分ける

形式化では「主張を書く」と「証明を書く」を分けられる。
主張の依存(定義と型だけ)は証明の依存より真に小さいので、
**主張グラフは非循環でも証明グラフは循環する**ということが起こりうる。
`Skeleton`(主張)と `Found`(実装)を分けている本計画の構成は、
もともとこの分離に対応している。**測っていないので断定しない。**

## ★この測定の限界

1. **`cf.` が 36% あり、両義的である。** 引用は依存のこともある。
   上の「3つ全部」は `cf.` を落としていない(落とせば更に縮むが、
   真の依存も落ちる)。
2. **`pdftotext` 由来で目視していない。**
3. **Remark を一律に落とすのは乱暴である。** 実際 `[IUTchIII] Remark 3.9.5, (i)` は
   正則包を**定義**しており、我々はそれに依存している。
   本番の `.needs` で Remark を一律除外してはならない。
   ここでは「循環の原因を切り分ける」ためだけに落とした。

## ★器具への含意

`ProofObligation` の辺の意味を **(a)「証明が依拠している」に定める**べきである。
現在は明文化されていない。定めれば:
- グラフは(ほぼ)非循環になり、**左から右へ着手する**という読み方が正当化される
- `check.mjs` の「循環 0 件」という印字に意味が生まれる
- 前方参照・解説案内は `.needs` に書かない、という規律になる
